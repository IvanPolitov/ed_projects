# Проект 4. Booking System

## Цель

Сервис бронирования ресурсов, правильная работа с транзакциями, блокировками и
race conditions.

Пример предметной области: бронирование переговорных комнат или рабочих мест.

## Сущности

User, Room, Booking, Schedule

## API

- просмотр комнат;
- просмотр свободных интервалов;
- создание бронирования;
- отмена бронирования;
- просмотр своих бронирований.

## Главное требование

Две конкурентные операции не должны иметь возможность забронировать один ресурс
на пересекающееся время.

## Эксперимент

- Запустить десятки или сотни конкурентных запросов на один ресурс.
- Доказать тестом, что данные остаются корректными.

## Темы для изучения и применения

- transactions;
- isolation levels;
- row locks;
- PostgreSQL constraints;
- race conditions;
- deadlocks;
- retry транзакций;
- idempotency.

## Стек

FastAPI · asyncio · PostgreSQL · SQLAlchemy · Raw SQL · Alembic · pytest ·
