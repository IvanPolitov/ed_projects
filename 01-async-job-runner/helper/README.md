# Helper Module

## Назначение

Этот модуль — подготовительная часть Async Job Runner. Здесь нужно реализовать
небольшой набор переиспользуемых инструментов, которые потом будут применяться в
основной логике фоновых задач.

Главная идея: сначала спокойно разобраться с декораторами, логированием,
повторами и итераторами, а уже потом использовать их внутри `asyncio`-сервиса.

## Что нужно реализовать

### 1. Декоратор `@retry`

Сделай декоратор:

```python
@retry(times=3, delay=1, exceptions=(ConnectionError,))
def load_data() -> str:
    ...
```

Он должен:

- принимать количество попыток через `times`;
- принимать задержку между попытками через `delay`;
- принимать кортеж исключений, которые нужно перехватывать, через `exceptions`;
- повторять вызов функции, если она упала с одним из указанных исключений;
- логировать каждую неудачную попытку через `logging`;
- после последней неудачной попытки пробрасывать исходное исключение наружу;
- сохранять имя и metadata исходной функции через `functools.wraps`.

Минимальное ожидаемое поведение:

- если функция успешно выполнилась с первой попытки, декоратор сразу возвращает
  результат;
- если функция падает 2 раза и на 3-й раз срабатывает, наружу возвращается
  успешный результат;
- если все попытки закончились ошибкой, наружу выбрасывается последняя ошибка;
- исключения, которых нет в `exceptions`, не ретраятся.

### 2. Декоратор `@timeit`

Сделай декоратор:

```python
@timeit
def calculate() -> int:
    ...
```

Он должен:

- измерять время выполнения функции;
- писать результат через `logging`, не через `print`;
- логировать имя функции;
- возвращать исходный результат функции без изменений;
- корректно логировать время даже если функция завершилась исключением;
- сохранять имя и metadata исходной функции через `functools.wraps`.

Для измерения времени используй `time.perf_counter()`, а не `time.time()`.

### 3. Генератор или итератор задач

Сделай простой генератор или класс-итератор, который последовательно выдает
задачи для будущего Job Runner.

Например, на вход можно передать список словарей:

```python
tasks = [
    {"type": "sleep", "payload": {"seconds": 1}},
    {"type": "url_check", "payload": {"url": "https://example.com"}},
]
```

Ожидаемое поведение:

- задачи выдаются по одной;
- порядок задач сохраняется;
- после последней задачи итерация корректно завершается;
- пустой список задач не ломает код;
- логику можно будет потом переиспользовать в Project 1.

## Что покрыть тестами

- `@retry` возвращает результат успешной функции;
- `@retry` повторяет вызов после ожидаемой ошибки;
- `@retry` пробрасывает ошибку после исчерпания попыток;
- `@retry` не перехватывает неожиданные типы исключений;
- `@timeit` возвращает исходный результат;
- `@timeit` логирует выполнение функции;
- `@timeit` не скрывает исключения;
- генератор или итератор выдает все задачи в правильном порядке;
- генератор или итератор корректно работает с пустым списком.
